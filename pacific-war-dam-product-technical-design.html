1. 概要

本设计提出一个以 DAM 为资产系统、以结构化 metadata 为知识层、以 web 检索阅览为用户入口的 Pacific War 数字档案平台。系统既支持内部馆藏整理和版权治理，也支持公众或研究者通过关键词、时间线、地图、 人物、战役、单位、来源机构等维度探索内容。

核心判断： 如果目标偏“资产管理、权限、授权、批量导入、内部工作流”，以 ResourceSpace 作为 DAM 底座更合适； 如果目标偏“公开数字展览、叙事页面、Linked Data 发布”，Omeka S 更适合作为发布层。MVP 推荐先采用 ResourceSpace 或兼容 DAM 作为资产系统，再建设独立检索阅览门户。
Design Goal
让 Pacific War 内容被可信地保存、描述、检索、引用、阅览和受控分发。
Non-goal
不在 MVP 中实现完整博物馆藏品管理、在线众包转录、复杂版权自动判定、商业图库交易。
Assumption
内容包含多语种材料，涉及敏感影像、军事单位、战役地点、个人姓名、版权与来源机构约束。
Success Metric
90% 资产有核心 metadata；检索结果 P95 小于 1.5s；阅览页支持 citation/export；所有公开资产有明确权利状态。

2. 产品范围

内容类型

照片、地图、战报、书信、日记、报纸、传单、口述史、视频、音频、实物藏品图像、研究笔记。

管理对象

源文件、衍生文件、metadata、collection、人物/地点/战役实体、权限、版本、审阅状态。

访问入口

馆员后台、metadata 编辑台、公开检索页、高级搜索、阅览器、collection/exhibit 页面。

MVP 功能边界

  • 批量上传与资产入库：文件校验、checksum、AI Intake 草稿、馆员审核修改、提交后新建对象或附加到已有对象。
  • Metadata collection 管理：字段模板、controlled vocabulary、collection 层级、实体关联、批量编辑。
  • 检索：关键词、全文、facet、时间范围、地图、人物/地点/战役/单位筛选。
  • 阅览：IIIF 深度缩放图片、PDF/OCR 并排阅读、音视频播放器、transcript、引用与导出。
  • 权限：公开、登录可见、馆内可见、限制下载、敏感内容提示、到期/授权状态。

候选产品组合

方案 适用场景 说明
ResourceSpace + Custom Portal 资产运营优先 DAM 管源文件、权限、分享、批量处理；门户负责 Pacific War 专用检索、地图、时间线、阅览。
Omeka S + DAM Adapter 公开展览优先 Omeka S 管 item/site/exhibit；外部 DAM 或对象存储管大文件和下载权限。
Custom DAM-lite 强定制、长期研发 PostgreSQL + Object Storage + Search + Worker 自建，成本更高但数据模型最自由。

5. Metadata Model

Pacific War 内容需要比通用 DAM 更强的历史语义层。建议采用“核心描述字段 + 领域实体 + 权利/来源 + 技术 metadata” 的组合模型，既能兼容 Dublin Core / MODS / IIIF，也能服务战役、地点、人物、单位等检索体验。

核心实体

Entity 作用 关键关系
Asset DAM 中的数字文件或文件组，包含原始文件、衍生文件、技术 metadata。 belongs_to Item；has Derivatives；has Rights。
Item 可编目的历史对象，如一张照片、一封信、一份地图、一段口述史。 part_of Collection；depicts Person/Place/Event；has Asset。
Collection 馆藏、专题、批次、来源机构或策展集合。 has Items；has Subcollections；has Curator Notes。
Event 战役、行动、占领、投降、轰炸、迁移等历史事件。 occurred_at Place；occurred_on DateRange；involves Organization。
Person / Organization / Unit 人物、机构、军队、舰船、部队、摄影师、出版方。 creator_of Item；depicted_in Item；participated_in Event。
Place 岛屿、城市、战场、海域、基地、坐标范围。 location_of Event；depicted_in Item；supports GeoJSON geometry。

建议字段模板

字段组 字段 说明
Identity Identifier, Title, Alternative Title, Slug 稳定引用、展示标题、多语言标题、短 URL。
Historical Context Date / Date Range, Campaign, Battle, Theater, Unit, Vessel, Aircraft 支持按战役、战区、单位和装备检索。
Geography Place, Coordinates, GeoJSON Boundary, Modern Country, Wartime Jurisdiction 同一地名可关联现代地理与战争时期名称。
Description Abstract, Transcription, OCR Text, Language, Subject Tags 全文检索和阅览页展示。
Provenance Source Archive, Accession No., Donor, Original Carrier, Digitization Batch 保证来源可信、可回溯。
Rights & Sensitivity Rights Status, License, Expiry, Download Policy, Sensitive Content Flag 决定是否公开、是否允许下载、是否需要内容提示。
Technical Media Type, File Format, Dimensions, Duration, Checksum, Derivative Paths 由 DAM/worker 自动生成和维护。
Controlled vocabulary 建议： Theater、Campaign、Battle、Military Unit、Content Type、Rights Status、Sensitivity Level 使用受控词表； 人名、地名、机构名支持 alias、原文名、罗马字、中文译名、日文写法，避免检索碎片化。

6. Architecture

架构采用前后端分离的 web platform。DAM 作为 source of record 管理原始资产和权限，metadata service 管理知识模型，search service 建立跨字段、全文、facet、地理和向量索引，viewer service 提供 IIIF 和媒体阅览能力。

组件职责

组件 职责 候选实现
Web App / BFF 公开门户、后台入口、API 聚合、权限上下文、SEO。 Next.js / React；REST 或 GraphQL facade。
DAM Service 源文件、衍生文件、版本、下载权限、外部分享。 ResourceSpace；或自建 Asset API + S3/MinIO。
Metadata Service Item、Collection、Entity、Schema、关系、审阅状态。 PostgreSQL + JSONB；或 Omeka S adapter。
Search Service 全文、facet、地理、时间线、相似搜索。 OpenSearch / Elasticsearch；pgvector 可做 MVP。
Processing Workers OCR、转录、缩略图、AV 转码、metadata extraction、索引更新。 Tesseract、Whisper、ImageMagick、FFmpeg、ExifTool。
Viewer Service IIIF Image/Presentation、PDF、音视频、转录文本、citation。 Cantaloupe / IIIF server；Mirador/OpenSeadragon；PDF.js。

7. Data Lifecycle

  1. Ingest：上传原始文件或 CSV/manifest 批量导入，生成唯一 identifier。
  2. Process：执行 checksum、病毒扫描、格式识别、缩略图、OCR、转录、低清预览。
  3. Describe：选择模板，补充历史 metadata，关联人物、地点、事件、collection。
  4. Review：审核权利、敏感内容、公开范围、下载策略。
  5. Index：写入搜索索引、地理索引、时间线索引和实体图谱。
  6. Publish：公开门户可见；受限资产只显示可公开 metadata 或预览。

8. 检索设计

检索体验要服务两种用户：研究者需要精确过滤和引用，公众读者需要可探索的主题入口。建议同时提供 basic search、 advanced search、faceted browse、map browse 和 timeline browse。

能力 用户体验 技术实现
关键词与全文 搜索标题、说明、OCR、transcript、人名、地点别名。 OpenSearch multi-field index；中文/英文/日文分词配置。
Facets 按年份、战役、地点、内容类型、来源、语言、权利状态筛选。 Facet aggregation；字段规范化；空值策略。
时间线 拖动年份范围查看战争阶段、战役和资产分布。 DateRange normalization；uncertain date 支持。
地图 从太平洋地图进入岛屿、海域、城市、战场。 GeoJSON + bounding box；geohash / geo_shape index。
实体探索 点击人物、单位、舰船、战役，查看相关资产和关系。 Entity graph；relationship table；cached counts。
相似内容 从一张照片找到相似场景、同批次、同地点或同主题内容。 Visual/text embedding；metadata similarity boost。
Pacific War 特殊点： 地名和人名可能存在多语种、多时期、多拼写版本。检索索引必须包含 alias，例如 Manila / 马尼拉、 Guadalcanal / 瓜达尔卡纳尔、Iwo Jima / 硫磺岛，并保留原始文献写法。

9. 阅览设计

Image / Map Viewer

IIIF 深度缩放、旋转、全屏、局部引用、下载受控衍生图、地图坐标说明。

Document Viewer

PDF.js 或图像序列；OCR 文本并排展示；关键词命中高亮；逐页 citation。

Audio / Video Viewer

低码率流式播放；transcript 时间戳跳转；字幕；敏感内容提示。

阅览页信息结构

  • Primary media viewer：图片、PDF、音频或视频。
  • Title + Summary：标题、日期、地点、战役、来源。
  • Metadata panel：完整字段、实体链接、collection 路径、rights 状态。
  • Actions：复制引用、导出 metadata、添加到 researcher list、请求高分辨率下载。
  • Related items：同 collection、同战役、同地点、同人物、同来源批次。

11. 安全与治理

  • RBAC：Public、Researcher、Curator、Rights Reviewer、Admin 分层。
  • Asset-level policy：每个资产独立决定 preview、metadata、download、original file 可见性。
  • Sensitive content policy：暴力、遗体、战俘、私人信息、仇恨/宣传材料需要内容提示和访问控制。
  • Audit log：记录导入、metadata 修改、权限变更、发布、下载请求。
  • Preservation：checksum 定期校验、对象存储版本化、异地备份、导出包。
  • Privacy：个人信息和在世人物相关内容需要额外 review。

12. MVP Roadmap

Phase 交付内容 验收标准
Phase 0: Discovery 样本数据审计、metadata 字段草案、rights 分类、产品选择 PoC。 完成 200-500 条样本导入和字段覆盖率报告。
Phase 1: DAM Foundation 资产上传、对象存储、checksum、缩略图、基础 metadata、权限。 支持批量导入；管理员能完成 publish/unpublish。
Phase 2: Search & Viewer 门户首页、搜索结果、facet、阅览页、IIIF/PDF/AV viewer。 搜索 P95 小于 1.5s；阅览页可复制 citation。
Phase 3: Domain Knowledge 战役/地点/人物/单位实体、地图、时间线、相关内容推荐。 核心 Pacific War browse 维度可用；实体页自动列出相关内容。
Phase 4: Governance & Scale 审计报表、rights 到期提醒、数据质量检查、OAI-PMH/IIIF 外部发布。 每月 metadata quality report；外部系统可消费公开 API。

Open Questions

  • 首批内容规模：文件数量、总容量、平均文件大小、视频比例。
  • 公开访问策略：全部公开、部分登录、馆内 IP、或申请制下载。
  • 多语种范围：是否同时支持中文、英文、日文 metadata 和界面。
  • 历史实体来源：是否已有战役、地名、人名、单位 authority list。
  • 是否需要 Omeka 风格展览页面，还是只需要检索阅览型 portal。
